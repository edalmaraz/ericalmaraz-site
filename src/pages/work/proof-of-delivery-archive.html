Delivery proof is on file for every order, before anyone asks.

A carrier's proof of delivery expired before a wholesale buyer requested it. I built an archive so that cannot happen again. On its first full run, all 2,008 retail purchase orders matched a shipment record.

  • My roleI wrote the specification and set the rules. AI agents wrote the code and tests.
  • In serviceSince October 2026
  • SettingMulti-brand consumer goods: wholesale, retail and direct orders

The situation

Proof that a package arrived lives with the carrier, and carriers keep it for a limited time. Wholesale and retail customers can raise a dispute long after delivery. On one order, the carrier's record had already expired when the buyer asked for it.

The facts about an order were also spread across the store, the shipping platform, inventory and the retailer purchase orders that arrive over EDI. Answering "what happened to this order?" meant visiting each one.

My part, and the agents' part

I wrote the specification and set the rules: the archive may read from every system and write to none of them, and it has to stay inside a daily request budget for each source. AI coding agents wrote the code and the tests to that specification.

I decided what "finished" meant, then checked the result against real orders before trusting it.

What I built

  • An internal order record: the life of the order on one page, with its status and its EDI documents in a timeline.
  • A proof-of-delivery PDF that can be sent to a customer and carries only the brand's name.
  • The raw evidence: shipment records, label files and status snapshots.
  • A search page with plain status words, such as "In transit" or "No delivery scan", and filters for wholesale, retail, direct and marketplace orders.

The result

  • 2,008 of 2,008retail purchase orders matched to a shipment record
  • 66,910orders filed on the first full run, covering 56,334 packages
  • 0 missingorder records when 25,315 tracked orders were reconciled against the source

How this was counted. By the archive's own audit on its first full run, 27 October 2026. The collector and its nightly backup were both reporting healthy on 16 November 2026.

Not measured. Hours saved, or the number of disputes settled with a document from the archive. I would rather leave those blank than estimate them.

Limits and what is next

Direct connections to the carriers are still waiting on credentials, so some proofs are added by hand, by dropping a PDF into an inbox folder that the collector files. Connecting the carriers directly is the next step.

Built with Python, FastAPI, SQLite, the ShipStation API and generated PDFs.
