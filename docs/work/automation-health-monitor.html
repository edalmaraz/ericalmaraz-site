Five systems, case study 3 of 5, operations systems

574 recurring jobs, one inventory, and I can see which ones are broken.

Recurring work was scattered across three machines, with no single view of what runs, who owns it or what is broken. I built one inventory and put a health check behind it. On the day of the count it showed 28 jobs that needed repair.

  • My roleI set the ask, approved the specification and decide what counts as confirmed. AI agents wrote the code.
  • In serviceSince October 2026, on checks first built that September
  • SettingEvery recurring job I run: a laptop, an office server and a second server

The situation

I had four partial tools that each watched something, and they did not agree on what a project was or what healthy meant. A count one day found 59 scheduled tasks on one machine: 21 were leftovers from dead projects, and 11 were reporting a failure.

One task showed as failed while the page it served was answering normally. A scheduler's status is not the same as health, so I needed something that checked the real thing.

My part, and the agents' part

I asked for one page of everything that recurs, marked as automated, delegated or done by hand. I approved the specification, and I decide when an entry counts as confirmed.

AI agents did the research and the build. They drafted 546 entries from session records, notes and the schedulers themselves, in 25 worker runs. Those drafts are still marked for my review, and I say so below.

What I built

Real counts from the snapshot taken that evening. The other 10 of the 574 had no status in it. The order of the tiles is arbitrary.

The result

  • 574recurring jobs in one inventory: 256 automated, 308 delegated, 10 done by hand
  • 28 failingjobs visible on one page on the day of the count
  • 79 projectswith a maintenance contract, covering 285 recurring checks

How this was counted. From the health snapshot and the contract state files on the evening of 16 November 2026.

Not measured. Time saved, and how much sooner a failure gets fixed now that it is visible.

Limits and what is next

About half the inventory, 293 of 574 jobs, has no health check attached yet, and none of the AI-drafted entries has had my review. Today it is a working inventory and a drift detector. It is not yet a verified record, and I do not describe it as one.

Old alerts also linger: one check has been failing for more than 1,200 runs in a row. Raising an alert is easier than closing one, so the next step is to make stale findings expire or close themselves.

Built with Python, YAML, Windows Task Scheduler, launchd, systemd and static HTML.
